# M26: animate from a text prompt with Kimodo (2026-10-07)

The owner's next item after the faces: in-app animation beyond the bundled clips. NVIDIA's Kimodo
(the owner's clone at `D:\CODE\kimodo`, upstream `nv-tlabs/kimodo` at `1aece8c`) generates motion from a
sentence on the SOMA 77-joint skeleton; the new `motion` step wraps its CLI as upstream runs it and the
`anim` step retargets the result like a pack clip (IMPLEMENTATION M26).

## Install on the laptop

- `.venv-kimodo` from the `kimodo` dependency group (torch 2.8 cu128, Kimodo at the pinned commit with
  its own deps: it pins transformers 5.1, so the group is declared conflicting with `ml` and `skin`).
  Upstream says "Linux primarily tested, Windows via Docker": the native Windows install synced from the
  lock and ran without a patch.
- Model group `kimodo`: the SOMA-RP v1.1 denoiser (1.1 GB), the two LLM2Vec adapters (0.4 GB) and the
  gated Llama 3 8B Instruct text encoder (16.1 GB as safetensors; the owner's Hugging Face account has
  the access). The encoder download took about 40 min; overlapping download runs each opened their own
  partial file for the same shard and a stale lock then held up the first generation (fixed by one
  uninterrupted download and clearing `models/hub/.locks`). The shards were verified against the
  published SHA-256 before the bench.

## Three prompts on the nurse

`motion` with the defaults (5 s, seed 1, 100 diffusion steps, the text encoder on the CPU), then `anim`
with the three motion versions onto `bench_faithful_nurse`'s skinned rig (`160_rig_skin`), frames 0, 50,
100 and 149 rendered (`m26_motions.jpg`). Measured on the retargeted result (the nurse is 0.99 m tall;
her hips start at 0.48 m):

| prompt | generation | what came out |
|---|---|---|
| "A person walks forward." | 48.1 s | 150 frames at 30 fps; the hips travel 2.90 m forward (she walks out of the fixed camera frame), level |
| "A person waves with the right hand." | 45.1 s | the right hand rises from 0.48 m to 0.95 m, the hips stay; a wave with the correct hand |
| "A person jumps once." | 37.1 s | the hips rise from 0.49 m to 0.61 m once, the arms swing up; a jump |

Each generation includes loading the 16 GB encoder from disk and encoding on the CPU: the diffusion
itself is seconds. Before the bench, Kimodo's standard T-pose BVH through `bvh_clip` and the real `anim`
step posed the nurse in a clean T-pose (front and side rendered), which checked the SOMA → our-52 map
(SOMA's metacarpal finger joints skipped: our finger 1–3 are SOMA 2–4) and the forward axis.

VRAM: the denoiser only on the GPU (about 1 GB); RAM: the encoder in bf16, about 16 GB while a prompt
is encoded (not sampled precisely).

## Owner's first run (2026-10-07)

On the viking: `520_anim` with a custom motion, "it does work foundationally"; the animation's name was
the version number. Now a motion's animation is named from its prompt ("A person waves with the right
hand." → "Waves with the right hand"; a second motion with the same prompt gets the version number
appended), in the viewer's menu and the exports; `anim` picks a motion by its version name and carries
the readable name through. Motions generated before this keep their number name.
