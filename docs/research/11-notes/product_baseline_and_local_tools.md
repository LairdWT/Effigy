# Retexturing feature baseline: commercial products and ready-made local tools (state as of 2026-10-08)

Scope: fact sheet (1) for commercial 3D-generation products with a "retexture" feature, fact sheet (2) for ready-made local / open tools, then the bar a local pipeline should meet. "Retexture" here = new texture set for a finished game mesh with its own UVs (text prompt, reference image, more detail, proper PBR, masked local edit), UVs kept. Pricing of commercial products is for comparison only.

Research caveats that apply throughout: reddit.com is blocked for this crawler, so "user complaints" come from Polycount, vendor help forums, vendor troubleshooting pages and third-party reviews; csm.ai did not resolve from this environment and tripo3d.ai blog pages returned 403, so several details come from search snippets of those pages rather than full reads. Dates and version numbers are given wherever a source states them.

---

## Key question 1: What does "Retexture" concretely do in Meshy and Tripo in 2026 (inputs, outputs, resolution, PBR, UV handling, time, cost), and what do users praise or complain about? (Product fact sheet)

### Takeaway
Both market leaders retexture an uploaded GLB/FBX/OBJ from a text prompt or a reference image in about 1–2 minutes for roughly $0.10–0.30, output base color plus optional metallic/roughness/normal at 2K default (4K/8K paid), and both re-unwrap by default — Meshy exposes an `enable_original_uv` flag (default false), Tripo's texture endpoint documents no UV option at all. Masked local edits exist in both (Meshy Texture Edit, Tripo Magic Brush) but only as viewport brush-mask + prompt regeneration; neither offers per-material prompts or per-view accept/reject. The recurring quality complaints are baked lighting (now addressed by "Remove Lighting"/"delight" toggles), seams from auto-UVs, smearing/blur on fast tiers, and soft facial detail.

### Cited Findings

#### Meshy (Meshy-6 Jan 2026, Meshy-7 Aug 2026)
- Inputs (web app AI Texturing): text prompt describing the material style, or an image prompt ("Upload an image of the desired material style"); mesh from My Models or upload of OBJ/FBX/GLB up to 50 MB. No mask or per-part prompt on this page. — [Meshy AI Texturing guide](https://docs.meshy.ai/en/webapp/guides/3d-model/ai-texturing)
- Outputs: with "Generate PBR Maps" on: Albedo, Normal, Roughness, Metallic; off: albedo only. Texture Resolution 2K / 4K / 8K. "Remove Lighting" toggle removes baked shadows ("Off: preserves original lighting info"). The page warns that overlapping UVs cause seams and recommends running Unwrap UV first. — [Meshy AI Texturing guide](https://docs.meshy.ai/en/webapp/guides/3d-model/ai-texturing)
- API `POST /openapi/v1/retexture` (current): input `input_task_id` or `model_url` (.glb/.gltf/.obj/.fbx/.stl); exactly one of `text_style_prompt` (≤800 chars), `image_style_url`, or `multiview_image_urls` (1–4 images, requires `meshy-7`); `ai_model` ∈ {meshy-6-lite, meshy-6, meshy-7, latest}; `enable_original_uv` default **false** ("Keep the model's existing UV layout instead of generating a new one"); `enable_pbr` default false (adds metallic, roughness, normal); `texture_resolution` ∈ {2k (default), 4k, 8k} (4k/8k need meshy-6/7); `remove_lighting` default true (meshy-6 only); output `texture_urls` = base_color always, metallic/normal/roughness when PBR on, `emission` only for meshy-6 (not 6-lite, not meshy-7, not at 8K). Docs recommend `enable_original_uv: true` for Meshy-generated models and false for third-party models "so Meshy can unwrap fresh UVs (best for models that lack proper UV mapping)". No face limit stated. — [Meshy API: Retexture](https://docs.meshy.ai/en/api/retexture)
- Older fal.ai wrapper of "Meshy 5 Retexture": `text_style_prompt` ≤600 chars, `image_style_url` takes precedence, `enable_original_uv` default **true** there, `enable_pbr` default false, $0.30 per generation. — [fal.ai Meshy v5 retexture](https://fal.ai/models/fal-ai/meshy/v5/retexture/llms.txt)
- PBR tutorial (dated July 21, 2026): maps = Albedo, Roughness, Metallic, Normal, plus Emission on Meshy-6+; base color 2K/4K/8K (8K needs Meshy-6+), PBR maps up to 4K; 2K on Free plan, 4K/8K paid; normal convention OpenGL +Y (glTF); albedo sRGB, others linear; metallic should be pure 0/1. "Uploaded models are automatically unwrapped (projection, seam placement, and texel density)"; textures are baked to the model's UV layout and are not tileable. Times/costs: 2K ≈1 min / 10 credits, 4K ≈1 min / 10 credits, 8K ≈2 min / 15 credits. Known limitations: "Multi-view projection reduces UV seams but can't guarantee they're invisible on complex UV layouts"; Texture Edit's Healing tool can patch them; Unity smoothness vs roughness confusion; OBJ exports ship maps as separate files. — [Meshy PBR texturing tutorial](https://www.meshy.ai/tutorials/pbr-texturing-with-meshy)
- API pricing: Retexture 10 credits at 2K/4K, 15 credits at 8K; prepaid credit system. — [Meshy API pricing](https://docs.meshy.ai/en/api/pricing). Credits guide (posted July 30, 2026): Free plan 100 credits/month; Retexture (Text to Texture) 10 credits; no separate price listed for Texture Edit or Smart Healing. — [Meshy credits guide](https://www.meshy.ai/tutorials/meshy-credits-guide). A third-party listing puts Pro at $20/month for 1,000 credits (≈$0.02/credit → ≈$0.20–0.30 per retexture; my arithmetic). — [fitgap Meshy listing](https://us.fitgap.com/products/045174/meshy)
- Texture Edit (masked local edit): "Paint-based texture editing directly on your 3D model with real-time preview"; workflow = open textured model → enter Texture Edit mode → orbit to the angle → "Draw a mask over the target region → Enter a text prompt describing the desired look → Generate"; Smart Healing Tool: "Paint over the artifact or seam → The tool auto-blends the area"; full undo/redo; tip: "Work from multiple angles to ensure edits blend seamlessly across the UV seams". Whether PBR maps are updated by an edit, the edit resolution and the cost are not stated. — [Meshy Texture Edit guide](https://docs.meshy.ai/en/webapp/guides/texture-edit). Help article: selection via click on a part ("highlighted with a light green outline"), brush or lasso with size; the edit window shows the original texture, not the PBR preview. — [Meshy Intercom: How to use Texture Edit](https://intercom.help/meshy/en/articles/11936711-how-to-use-texture-edit)
- Version timeline: Meshy 6 listed as released January 18, 2026 with retexture as one input mode, plus Low Poly Mode. — [There's An AI For That: Meshy 6](https://theresanaiforthat.com/model/meshy-6/). Meshy 7 released August 10, 2026 (announced August 12), shipping as three models: Image to 3D, Multi Image to 3D, Retexture; Retexture "Rewraps an existing GLB in a brand-new material without changing the geometry… render at 2K, 4K, or 8K with optional PBR maps"; Meshy 7.1 on September 10, 2026 adds Ultra 4K geometry (competitor blog, verify against Meshy's changelog). — [Neural4D: Meshy 7 release date](https://blog.neural4d.com/comparisons/meshy-7-release-date-and-alternative/); [Scenario: Meshy essentials (updated Aug 12, 2026)](https://help.scenario.com/articles/5709143930-meshy-the-essentials)
- Vendor-authored hands-on of the 8K release (HackerNoon, July 23, 2026; author is a Meshy designer): "An 8K result in about two minutes"; de-lighting "Cleanest of what I tested — most neutral base color, least baked-in shadow"; verdict "Resolution is the price of entry; de-lighting is the competition… If 4K survives your closest shot, don't pay for 8K"; caveat "Texture quality can't fix geometry". — [HackerNoon Meshy 8K](https://hackernoon.com/i-ran-the-same-models-through-meshy-8k-ai-texturing-resolution-detail-and-de-lighting)
- Meshy's own seam/smear guidance: "Place seams in low-visibility areas — under arms, behind ears, along symmetry lines"; pad UV islands ≥4 px at 1K and 8 px at 2K; "Smearing usually means the texture isn't following the geometry underneath it"; "Switch to Meshy 7, our newest texturing model. It's built around keeping the texture aligned to the surface"; "if the mesh has overlapping or badly packed UV islands, no texturing model can fully compensate. Run Remesh… then re-texture"; for hero close-ups "add a hand-painted touch-up pass in Substance Painter or Photoshop on the seam regions". — [Meshy AI Texture Generator page](https://www.meshy.ai/features/ai-texture-generator)
- Complaint evidence (non-Reddit): Meshy's Unreal plugin docs document textures that "look blurry after import" until forced to stream (engine-side, not generation). — [Meshy Unreal plugin troubleshooting](https://docs.meshy.ai/en/webapp/plugins/unreal/troubleshooting). Formlabs forum user: preview looked great but the downloaded textured STL "looked awful… extremely low resolution"; Formlabs attributed it to Meshy's automated meshing. — [Formlabs forum: Texture Engine / Meshy](https://forum.formlabs.com/t/texture-engine-meshy-not-working/38452). A rival's review (Framia) lists cons: messy topology needing retopo, organic shapes "such as hands can look melted"; pros praise the PBR texturing. — [Framia Meshy review](https://framia.converge.ai/blog/meshy-ai-review). Toolradar aggregated: "quality varies", "better for drafts". — [Toolradar Meshy](https://toolradar.com/tools/meshy)
- Preference claim: "preferred over Tripo 3.1 by 63.8% in a blind benchmark of 1,331 senior 3D artists" (vendor-promoted, measures mesh more than texture). — [Meshy vs Tripo (Meshy)](https://www.meshy.ai/vi/compare/meshy-vs-tripo); [3D AI Studio Meshy-6 page](https://www.3daistudio.com/Models/Meshy-6)

#### Tripo (Tripo 3.x, texture model v3.5-20260815)
- API `POST https://openapi.tripo3d.com/v3/models/texture` "Regenerate texture maps for an existing model": `input` = task_id, file_token or URL (GLB/GLTF/FBX/OBJ/STL, ≤150 MB); `model` ∈ {v3.5-20260815 (newest; required for `texture_quality=fast` and `delight`), v3.0-20250812 (default), v2.5-20250123}; `texture_prompt` with `text` (+ optional `style_image`, ≥256×256 recommended), or `image`, or `images` (exactly 4: front/left/back/right) — mutually exclusive; `pbr` default **true**; `texture_seed`; `texture_alignment` ∈ {original_image (default), geometry}; `texture_quality` ∈ {fast, standard (default), detailed, extreme = "8K textures and highest fidelity… Costs additional credits compared to detailed"}; `part_names` from a previous segmentation task ("If omitted, all parts are textured"); `bake` default true ("Bake advanced material effects into base textures for broader compatibility"); `delight` default true ("Removes baked-in lighting from the reference image before texturing", v3.5 only). **UV handling is not documented**; no face limit stated; the sample shows `created_at` 12:00:00Z → `completed_at` 12:01:30Z (example only). — [Tripo developers: texture endpoint](https://developers.tripo3d.com/en/docs/models-texture.md)
- Pricing: "1 credit = $0.01 USD"; standalone "Model Processing" texturing: Texture (Fast) 10, Texture (Standard) 10, Texture (HD) 20, Texture (8K Ultra) 30 credits; add-on surcharges HD Texture +10, 8K Ultra Texture +20 (the page's table and add-on list disagree: 30 vs +20 for 8K). — [Tripo developers pricing](https://developers.tripo3d.ai/en/pricing). Platform docs for P1: texture_quality standard +10, detailed +20, extreme +30 credits. — [Tripo platform docs: generation](https://platform.tripo3d.ai/docs/generation). Consumer Max plan $90/month includes "Unlimited Access to 8K Textures". — [Tripo pricing](https://www.tripo3d.ai/pricing)
- ComfyUI wrapper docs: V2 texture node produces PBR maps or plain color; quality tiers standard / detailed (HD) / extreme (8K); `texture_alignment` is about aligning to the source image vs geometry, not about preserving input UVs. — [ComfyUI TripoTextureNodeV2](https://docs.comfy.org/built-in-nodes/TripoTextureNodeV2.md)
- Texture module in Tripo Studio = Texture Gen (full), Texture Upscale (to 4K; "8K still in progress" per one post, "upscale to 8K" per the Vietnamese feature page — status unclear), PBR Generator, Magic Brush ("fits between full generation and upscaling as the tool for localized edits"). Texture Upscale "leaves the underlying content alone and mostly enhances what is already there, so flaws in the base texture become more visible"; API upscale 10 credits. — [Tripo blog: repaint part of 3D texture](https://www.tripo3d.ai/blog/repaint-part-of-3d-texture); [Tripo blog: upscale & retexture](https://www.tripo3d.ai/blog/upscale-retexture-existing-model); [Tripo: 3D texture upscaling (vi)](https://www.tripo3d.ai/vi/features/3d-texture-upscaling)
- Magic Brush UX: Gen mode "for material changes and new details", Paint mode "for color adjustments and blemish fixes"; "Both modes are scoped to the brushed region"; interface shows a texture preview and a camera preview; adjust prompt → regenerate preview → "Save Texture" to commit. — [Tripo blog: how to use Magic Brush (ru)](https://www.tripo3d.ai/ru/blog/how-to-use-magic-brush); [Tripo blog: repaint specific area](https://www.tripo3d.ai/blog/repaint-specific-texture-area)
- Tripo's own failure-mode guides (complaints the vendor acknowledges): "UV mapping in AI models can produce visible seams or stretched textures on complex shapes"; "Fast generation settings smooth over fine detail… comes out looking soft"; free tiers "often ship with 1K or 2K textures that look soft when you zoom in"; for faces "re-balancing your UV layout to give more texture space to important areas (like a character's face)"; overlapping geometry gives "black spots, shading seams" in normal baking. — [Tripo: common failure modes](https://www.tripo3d.ai/blog/explore/common-failure-modes-of-ai-3d-generators-and-fixes); [Tripo: why AI 3D models look bad](https://www.tripo3d.ai/blog/why-ai-3d-models-look-bad); [Tripo: bad topology](https://www.tripo3d.ai/blog/why-ai-3d-models-have-bad-topology)
- Tripo recommends fixing geometry (Smart Mesh) before retexturing because "a texture applied over messy topology gives poor results". — [Tripo blog: upscale & retexture](https://www.tripo3d.ai/blog/upscale-retexture-existing-model)
- Third-party comparison (Aug 2026, qualitative, no measurements): Meshy "every generated texture includes PBR maps like Albedo, Roughness, Metallic, and Normal"; Tripo's PBR support and UV handling listed as "Limited public information" / "Not publicly detailed"; verdict Meshy better overall for texture control, Tripo for speed. — [e-architect: Meshy vs Tripo texture generation](https://mail.e-architect.com/articles/meshy-vs-tripo-ai-3d-texture-generation). Another comparison says generated UVs "often overlap and distribute texel density poorly". — [nhance: Meshy vs Tripo for game art (2026)](https://nhance-school.com/tools/compare/meshy-vs-tripo-ai)

- Pilgway 3DCoat 2026 / 3DCoatTextura 2026 (July 2026): node-based GPU texturing "in the same vein as Substance 3D Designer and Mari" (no AI retexture claimed). — [CG Channel: 3DCoat 2026](https://www.cgchannel.com/2026/07/pilgway-releases-3dcoat-2026-and-3dcoattextura-2026/)

### Inferences
- The de-facto commercial baseline in Oct 2026: text or single reference image in; base color + metallic/roughness/normal (OpenGL normal) out; 2K default, 4K common, 8K as a premium tier that only changes base color; 1–2 minutes per asset; ≈$0.10–0.30 per run; delighting on by default. A local pipeline that delivers 2K–4K base color + M/R/N with delighted albedo in a few minutes on a 16 GB GPU matches the baseline; 8K is not needed (Meshy's own author says so).
- UV preservation is a weak spot of the commercial tools: Meshy defaults to re-unwrapping third-party meshes and Tripo does not document UV behaviour at all; Rodin requires UVs but does not promise to keep them. "UVs kept" is therefore a differentiator for a local game-asset pipeline, not table stakes.
- The complaints that recur across vendor troubleshooting pages and forums are exactly the failure modes of multi-view projection texturing: seams at UV islands, smearing where the projection does not follow geometry, soft detail on fast/low-res tiers, baked lighting, and faces/lettering needing a manual pass. Vendors' answers are (a) delighting, (b) healing/magic-brush local inpainting, (c) "fix the mesh/UVs first", (d) hand touch-up in Substance Painter.
- Mask-based local edit is now expected (Meshy Texture Edit, Tripo Magic Brush, CSM brush projection, Hunyuan edit layer); per-material prompts are only hinted at (Tripo `part_names`, Hunyuan part segmentation); per-view accept/reject does not exist in any commercial tool found.

### Gaps
- No independent, quantified 2026 benchmark of Meshy vs Tripo retexture quality (seams, delighting, face detail) was found; the available comparisons are vendor- or reseller-authored. Reddit threads could not be searched (domain blocked for this crawler).
- Tripo: UV handling of the texture endpoint, typical duration, and exact credit cost per texture tier are inconsistent across Tripo's own pages (table says 30 credits for 8K, add-on list says +20).
- Meshy Texture Edit: cost per edit, edit resolution, and whether PBR maps are regenerated for the masked region are not documented.
- Rodin texture-only: whether output keeps the input UV layout is not stated; the required plan tier is ambiguous on the page.
- CSM and Polycam pages could not be fetched (DNS / 403); details rest on search snippets. Luma Genie's current status is unknown (site no longer mentions it).
- Kaedim's "Six-View Texturing" page is gone; no self-serve retexture product documented.
- Whether Hunyuan 3D Studio's part-level/local editing is exposed in a shipped product (vs the paper) is unconfirmed; irrelevant for this project because Hunyuan is excluded.

## Key question 2: Which local tools already deliver a usable text/image-driven retexture on a consumer GPU, which models do they rely on, and are those models commercial-clean? (Local / open tools fact sheet)

### Takeaway
Two local tools deliver an end-to-end text/image-driven retexture on a 16 GB consumer GPU today: StableGen (Blender add-on, GPL-3.0, ComfyUI backend, SDXL/FLUX/Qwen with Depth/Normal/Canny ControlNets + IPAdapter, projection → weighted blend → UV bake, PBR via Marigold/StableDelight) and StableProjectorz (standalone Windows Unity app, AGPL-3.0 since Jan 2026, A1111/Forge backend, SDXL-era projection painting, UV-preserving, UDIM). ## Key question 3: Which UX elements make retexturing usable (mask painting in the viewport, per-material prompts, seam preview, view-by-view accept/reject, style reference), as seen in the best tools?

### Takeaway
The usable pattern across the best tools is: generate a full pass from text + style/reference image, then iterate with viewport-masked local regeneration ("brush → prompt → preview → commit") plus a one-click healing brush for seams, with undo/redo and a live preview that updates on the model. Per-camera prompts and per-camera regeneration exist locally (StableGen); per-view accept/reject and per-material prompts are missing almost everywhere (Tripo exposes `part_names`, Hunyuan's paper has part segmentation).

### Cited Findings
- Meshy Texture Edit: orbit to the angle, draw a mask, text prompt, generate, "Preview the result in real time"; Smart Healing: paint over seam/artifact, auto-blend; "Full edit history with undo/redo support"; advice to "Work from multiple angles… across the UV seams"; recommended loop = AI Texturing base → Texture Edit refinement. — [Meshy Texture Edit](https://docs.meshy.ai/en/webapp/guides/texture-edit). Part click-selection with green outline, brush or lasso. — [Meshy Intercom help](https://intercom.help/meshy/en/articles/11936711-how-to-use-texture-edit)
- Tripo Magic Brush: Gen vs Paint modes scoped to the brushed region; texture preview + camera preview side by side; adjust prompt → new preview → "Save Texture". — [Tripo Magic Brush how-to (ru)](https://www.tripo3d.ai/ru/blog/how-to-use-magic-brush); [Tripo: repaint part of texture](https://www.tripo3d.ai/blog/repaint-part-of-3d-texture)
- Tripo API: `style_image` alongside `text`; 4-view `images` input (front/left/back/right); `part_names` to texture only chosen parts; `texture_alignment` original_image vs geometry; `texture_seed` to vary texture on fixed geometry. — [Tripo texture endpoint](https://developers.tripo3d.com/en/docs/models-texture.md)
- Meshy API: text style prompt, image style, or 1–4 multiview images (meshy-7); original-UV toggle; resolution and PBR toggles; SSE progress stream. — [Meshy Retexture API](https://docs.meshy.ai/en/api/retexture)
- CSM: reference-image brush projection, rotate to cover every side, mirror toggle, save. — [CSM Academy: fix logos](https://www.csm.ai/academy/fix-logos-and-writing-elements-with-ai-retexturing)
- Hyper3D: prompt + reference image + `reference_scale`, PBR/Shaded/All, 2K/4K. — [Hyper3D API page](https://hyper3d.ai/features/api)
- StableGen: seven camera placement strategies, per-camera aspect from silhouette, per-camera prompts to regenerate specific views, Local Edit by pointing cameras (angle + vignette feathering), mask blur/grow, Refine/Restyle img2img on existing textures, Preview Gallery to pick a candidate (for TRELLIS.2 only); brush inpainting planned. — [StableGen README](https://github.com/sakalond/StableGen)
- StableProjectorz: paint blend weights per projection directly on the model to mix projections and remove seams; img2img inpaint mask limits projection to selected areas; per-projection HSV/contrast; baked AO over all projections; black unseen patches are painted over in a follow-up projection. — [stableprojectorz.com](https://stableprojectorz.com/); [Habr article](https://habr.com/en/articles/822089); [STYLY tutorial](https://styly.cc/tips/ai-stablediffusion-stableprojectorz/)
- Blender native: Quick Edit → external editor → Apply (project back); Apply Camera Image; Seam Bleed; Occlude; Backface Culling. — [Blender manual: Texture Paint options](https://docs.blender.org/manual/en/latest/sculpt_paint/texture_paint/tool_settings/options.html)
- Substance Sampler: four variations per prompt, drag into layers, refine by prompt without leaving the app. — [Adobe Sampler generative workflows](https://experienceleague.adobe.com/en/docs/substance-3d-sampler/using/features-and-workflows/generative-workflows)
- Hunyuan3D Studio (reference): natural-language global and local edits; image-guided editing; part-wise material segmentation for localized edits. — [arXiv 2509.12815](https://arxiv.org/html/2509.12815v1)
- Kaedim (human pipeline): UV step with "Auto approve" toggle vs manual review before texturing — the only explicit stage-gate approval found. — [Kaedim docs](https://docs.kaedim3d.com/llms-full.txt)
- Artist sentiment: "the generation step is no longer the problem — topology and textures come out reasonably usable for props and backgrounds… How are you actually handling AI-generated mesh cleanup before engine handoff?" — [Polycount Technical Talk](https://polycount.com/categories/technical-talk). Seam removal "was easier or rather more controllable to do in Photoshop or any non destructive vector editor". — [Polycount: AI materials, any progress?](https://polycount.com/discussion/235632/ai-materials-any-progress-recently)

### Inferences
- Minimum UX for a local retexture to feel "as good as Meshy/Tripo": (1) text + optional style image for the full pass; (2) viewport mask → prompt → regenerate only that region; (3) a seam/heal brush (inpaint along UV-island borders); (4) undo/redo with a live viewer; (5) an "original UV" guarantee. Everything else (per-camera prompts, per-view accept/reject, per-material prompts via a part/material mask) would exceed the commercial baseline and is where a local tool can win.
- Because a game mesh already has materials/UV islands, per-material prompts can be implemented trivially as mask = material slot (the project's Blender headless ops already know the material slots), which no commercial tool offers; Tripo's `part_names` is the closest analogue.
- A view-by-view accept/reject (choose among N candidates per camera, then blend) mirrors StableGen's Preview Gallery idea and StableProjectorz's blend-weight painting; both show the pattern is natural for projection pipelines.

### Gaps
- No usability study or timing data (edits per hour, seconds per local edit) was found for any tool; iteration speed is described only qualitatively ("in seconds", "about a minute").
- Whether Meshy's healing brush operates in UV space or in screen space is not documented.

## Key question 4: Is any local tool's code permissively licensed and clean enough to port parts from (projection, inpainting order, seam handling)?

### Takeaway
No complete local retexture tool is permissively licensed: StableGen is GPL-3.0, StableProjectorz is AGPL-3.0 (Unity/C#), Dream Textures and Pallaidium are GPL-3.0. Permissive, portable pieces exist at the component level: ComfyUI-3D-Pack (MIT, but its baker uses nvdiffrast), ComfyTextures (MIT, Unreal/C++ and ComfyUI JSON), Paint3D (Apache-2.0: depth-inpaint ordering, UV-position ControlNet, UV-space inpainting), MV-Adapter (Apache-2.0: geometry-conditioned multi-view generation with mesh input), Marigold and StableDelight (Apache-2.0: PBR decomposition / delighting). Approaches and UX can be copied from the GPL/AGPL tools without copying code; the project's own MIT code must not vendor them.

### Cited Findings
- StableGen: GPL-3.0; optional nvdiffrast/nvdiffrec path non-commercial. — [StableGen README](https://github.com/sakalond/StableGen)
- StableProjectorz: AGPL-3.0 since January 2026; "if you distribute modified versions or run it as a network service, you must also make your source code available under AGPL-3.0"; Unity 6000 project; projection into an accumulation UV render target per UDIM slice with depth-respecting bake then dilation. — [stableprojectorz.com](https://stableprojectorz.com/); [StableProjectorz GitHub](https://github.com/IgorAherne/StableProjectorz)
- Dream Textures: GPL-3.0. — [Dream Textures README](https://github.com/carson-katri/dream-textures). Pallaidium: GPL-3.0 plus usage restrictions. — [Pallaidium README](https://github.com/tin2tin/Pallaidium)
- ComfyUI-3D-Pack: MIT; mesh-fitting baker "using Nvdiffrast". — [ComfyUI-3D-Pack README](https://github.com/MrForExample/ComfyUI-3D-Pack)
- ComfyTextures: MIT; SDXL + ControlNet depth/canny; single-POV projection; multi-POV WIP; no seam handling. — [ComfyTextures GitHub](https://github.com/AlexanderDzhoganov/ComfyTextures)
- Paint3D: "distributed under an Apache 2.0 LICENSE"; depth-based inpainting then UV-based inpainting; kaolin + PyTorch3D dependencies; output "lighting-less". — [Paint3D GitHub](https://github.com/OpenTexture/Paint3D)
- MV-Adapter: Apache-2.0; SDXL/SD2.1; mesh-conditioned text/image → multi-view → textured GLB. — [MV-Adapter GitHub](https://github.com/huanngzh/MV-Adapter)
- Marigold: Apache-2.0 (since Dec 2023). — [Marigold GitHub](https://github.com/prs-eth/marigold?ref=aiartweekly). StableDelight: Apache-2.0. — [StableDelight GitHub](https://github.com/Stable-X/StableDelight)
- ArmorPaint: source zlib (CG Channel / Digital Production), binaries paid; C codebase; neural nodes are an external-process bridge. — [CG Channel: ArmorPaint 1.0](https://www.cgchannel.com/?p=178507); [Digital Production](https://digitalproduction.com/2026/09/12/armorpaint-1-0-swaps-haxe-for-c/)
- Blender's extensions platform requires GPL-3.0-or-later for listed add-ons, which is why Blender add-ons in this space are GPL. — [Blender manual: extension licenses](https://docs.blender.org/manual/ja/4.2/advanced/extensions/licenses.html)

### Inferences
- The Effigy split (MIT core, GPL `blender_ops/` as a separate process) is compatible with reading StableGen's Blender-side projection ideas (OSL / Raycast-node projection, Smart-UV-vs-existing-UV bake) and reimplementing them inside `blender_ops/` (GPL-3.0-or-later) — GPL-3.0 code could even be vendored there, but AGPL (StableProjectorz) should not be mixed in at all.
- For the torch side (MIT), the portable, licence-clean building blocks are: MV-Adapter's geometry-conditioned multi-view generation, Paint3D's "depth-inpaint sequential views → UV-space inpaint of holes" ordering and UV-position ControlNet, StableDelight for albedo delighting, Marigold IID for roughness/metallic/normal estimation, and the project's own `uvraster` for projection/bake instead of nvdiffrast/kaolin.
- ArmorPaint's zlib C code is permissive but is a painter engine; its only retexture-relevant idea (external process for neural inference, output read back as a texture) is architectural, not code to port.

### Gaps
- Paint3D's kaolin 0.13 and PyTorch3D dependency chain has not been checked against torch 2.8 cu128 / sm_120 / no-nvdiffrast; porting would mean re-implementing its renderer on `uvraster`.
- Licence fields of ComfyUI custom-node wrappers (ComfyUI-Paint3D-Nodes, MV-Adapter ComfyUI nodes) were not verified.

## Key question 5: What resolution and PBR completeness do game developers expect from a retexture in 2026?

### Takeaway
Guides and the commercial defaults converge on 2K as the standard per-asset resolution (1K for generic props, 4K reserved for hero assets and main-character faces), with a full PBR set of Base Color + Normal + Roughness + Metallic (+ AO, often packed as ORM), OpenGL-convention normals for glTF, and delighted albedo. 8K is marketed but even Meshy's own author says most production assets do not need it.

### Cited Findings
- Resolution guide (April 12, 2026): characters 4K for main-character/boss faces, 2K for torsos; hero props 2K standard, 4K for closely inspected inventory/shop items; generic props 1K default (chairs, crates, barrels), 512 for pebbles/debris; environments 2K for walls/floors, 1K trim, 4K terrain base; texel density targets mobile/VR 256–512, third-person 512–1024, first-person 1024–2048, cinematic 2048–4096 texels/m; "full PBR set" = Base Color, Normal, ORM (AO+Roughness+Metallic packed); mismatched density between neighbouring surfaces is a bigger giveaway than raw resolution; defaulting everything to 4K bloats VRAM. — [Strayspark: texture resolution guide](https://www.strayspark.studio/blog/texture-resolution-guide-games-512-1k-2k-4k)
- Maxon's texel-density presets: first-person e.g. 10.24, third-person 5.12, top-down ≤2.56 (px/cm) — "the closer the camera is to the asset, the higher the Texel Density should be". — [Maxon C4D 2026: Texel Density](https://help.maxon.net/c4d/2026/en-us/Content/html/Texel_Density.html). Polycount: UT2K4-era characters used 2048 textures on ≈1.8 m models (≈11.3 ppc), and density has risen since. — [Polycount comment](https://polycount.com/discussion/comment/2304812/)
- Commercial defaults: Meshy 2K default, 4K/8K paid, PBR maps up to 4K, OpenGL +Y normals, albedo sRGB, metallic 0/1. — [Meshy PBR tutorial](https://www.meshy.ai/tutorials/pbr-texturing-with-meshy). Tripo standard/HD/8K Ultra tiers, `pbr` default true, `delight` default true. — [Tripo texture endpoint](https://developers.tripo3d.com/en/docs/models-texture.md); [Tripo pricing](https://developers.tripo3d.ai/en/pricing). Rodin 2K basic / 4K high, PBR = base color, metallic, normal, roughness. — [Hyper3D API page](https://hyper3d.ai/features/api). Kaedim offers 1024/2048/4096 and the full map list incl. AO, displacement, emissive. — [Kaedim docs](https://docs.kaedim3d.com/llms-full.txt)
- Delighting is now a headline criterion: "Resolution is the price of entry; de-lighting is the competition"; "If 4K survives your closest shot, don't pay for 8K". — [HackerNoon Meshy 8K (vendor author)](https://hackernoon.com/i-ran-the-same-models-through-meshy-8k-ai-texturing-resolution-detail-and-de-lighting). Neural4D (vendor) describes the classic failure: shadows and highlights from the reference projected into the texture, "creating 'painted' shadows that look unnatural in a dynamic engine". — [Neural4D: baked shadows](https://www.neural4d.com/how-tos/how-to-solve-baked-shadows-and-lighting-issues)
- Padding/seams: UV islands padded ≥4 px at 1K and 8 px at 2K; seams placed under arms, behind ears, along symmetry lines. — [Meshy AI texture generator page](https://www.meshy.ai/features/ai-texture-generator). Blender's Seam Bleed exists for the same reason. — [Blender manual](https://docs.blender.org/manual/en/latest/sculpt_paint/texture_paint/tool_settings/options.html)
- Engine conventions that trip up imports: Unity smoothness = 1 − roughness; Unreal may need "Flip Green Channel" for OpenGL normals. — [Meshy PBR tutorial](https://www.meshy.ai/tutorials/pbr-texturing-with-meshy)
- Free tiers shipping 1K/2K "look soft when you zoom in"; faces need more UV space. — [Tripo failure modes](https://www.tripo3d.ai/blog/explore/common-failure-modes-of-ai-3d-generators-and-fixes)
- Artists on Polycount regard current AI output as "reasonably usable for props and backgrounds" and focus their questions on cleanup before engine handoff. — [Polycount Technical Talk](https://polycount.com/categories/technical-talk)

### Inferences
- Target spec for the local retexture of a 5k–20k-tri game asset: 2K per material by default, 4K opt-in for hero characters' faces/hero props; Base Color (sRGB, delighted), Normal (OpenGL, tangent space), Roughness, Metallic (linear, metallic near-binary), optional AO and emission; export packed ORM for Unity/Unreal/Godot profiles; ≥8 px padding at 2K on existing UV islands.
- "More detail" requests are better served by a 2K→4K upscale/refine pass on hero assets (Tripo's Texture Upscale, RTX Remix / ESRGAN-style upscalers) than by 8K generation.

### Gaps
- No 2026 Unity/Unreal/Godot community thread stating explicit expectations for AI-retextured assets was reachable (Reddit blocked; engine forums returned only generic lightmap-seam threads). The expectations above are inferred from art-direction guides and the vendors' tiering.
